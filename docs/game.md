# Guessing Day

A two-player guessing game for two phones, served by the Pi on port 8090. Both players draw a secret Fourth Wing character or dragon each round, ask each other yes/no questions out loud, and press **Got it** or **Forfeit** on their own phone.

Contract (phases, endpoints, the per-player view): `services/game/API.md`. Read it before changing the server or the page.

## Layout

```
services/game/
  *.go          pure state machine (game.go), per-player views (view.go), HTTP and SSE (server.go), flags (main.go)
  web/          the page: index.html, app.js, style.css (vanilla, no build step); mock/ has the dev mock and the browser checks
  content/      characters.json, and media/ for clips and posters (optional per character)
  rootfs/       the systemd unit; make build also stages web/ and content/ under usr/share/guessing-day/
```

## Rules the server enforces

- Two players at most. A third, or anyone joining mid-game, gets "The dragons have decided not to bond with you. Try again next year...".
- No accounts. A random token in the phone's `localStorage` lets a phone rejoin after a screen lock or a Wi-Fi blip.
- Either player sets the options on the lobby's Settings screen: rounds, round length (2, 3 or 5 minutes, default 3), hints on or off, and the pool (all, riders or dragons). They stay for the next game and reset when both players leave.
- Either player can end a game early with **End game** (two taps): both phones go back to the lobby with a note of who ended it, nothing goes to the history, and the bag still remembers the characters drawn.
- A correct guess scores 1, plus 2 in the first third of the round, plus 1 in the second third, whatever its length. A forfeit or timeout scores 0. Constants are in `game.go`.
- Characters come from a shuffle bag that is not reset between games: back-to-back games do not repeat a character until the deck runs low, and none repeats within one game. Only the chosen pool is drawn from. The bag is rebuilt from `history.jsonl` after a restart. A rider and their own partner dragon are never drawn in the same round.
- The guesser's view never contains the holder's secret: not the name, the id, the clip path, the colour, the partner nor the tips. `TestNoLeakBeforeRoundEnd` fails if it does.
- `history.jsonl` in the data dir gets one line when a game ends (scores, plus the secret ids that seed the bag; `/api/history` hides the ids), and nothing else writes to the SD card.

## Characters and clips

`content/characters.json` is an array. The game reads `id`, `name`, `kind` (`rider`, `dragon` or `other`), `partner` (never drawn together in one round), `color` (card frame, `#rrggbb`, absent for `other`) and `tips` (hints for the holder, vague to specific). Add `clip` and `poster` (file names under `content/media/`) to give a character an animation. During a game the whole phone screen is one carved stone slab (`hall()` in `web/app.js`): scores on two plaques, round and timer in the diamond at the top, Got it and Forfeit on the plinth, End game on the tab at the bottom. While a secret is held the slab's face is the character's `color` (dark stone for `other`), and the name sits on a dark banner in front of the kind's emblem: claw gouges for a dragon, crossed blades in a double ring for a rider, a cracked slab for `other`. **Hide** on the card blanks the kind, emblem, name and tips until tapped again. Round end shows the two secrets as half-size slabs with the same banner and emblem; on the last round its button reads "See the verdict". The final screen is its own: a dragon rider into the sunset for the winner, a scorch mark for the loser, two dragons for a tie, each with a few lines of text (`FINALE` in `web/app.js`). Changing screen sends a dragon's shadow across (`render()` in `web/app.js`); holding your own secret counts as one screen, so each phone sweeps when it draws, and not again when the other player does, and between game screens the shadow stays in the middle of the slab. With no clip the name is revealed with a rune animation: each letter starts as a cycling rune and settles on its letter, left to right (`web/runes.js`, generated by `tools/runes.mjs`). With a clip, the clip plays on the card face above the banner.

Clip format: portrait, about 720x1280, H.264 mp4, a few hundred kB, action in the centre because the page crops with `object-fit: cover`. The poster is the final frame as WebP or PNG.

## Run and test

```bash
make -C services/game test                     # go vet + go test (race-clean)
cd services/game && go run . -web web -content content -data /tmp/gd -listen :18090
node services/game/web/mock/live.mjs http://localhost:18090 /tmp/shots   # two phones, real server
platform/deploy.sh game                        # after make -C services/game build
```

The hub lists it as the **Guessing Day** button once `hub/rootfs/etc/pihub/services.d/game.json` is deployed and pihub restarted.
